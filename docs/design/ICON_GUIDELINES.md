# ICON GUIDELINES

**Project:** Project Genesis

**Version:** 1.0

**Status:** Planning

---

# Purpose

This document defines the icon language used throughout Project Genesis.

It ensures that every icon follows one consistent visual style,
supports usability, and communicates information quickly and clearly.

Icons are a supporting element.

They complement text.

They do not replace text.

---

# Design Philosophy

Icons exist to improve recognition.

They must never increase ambiguity.

An icon should answer:

"What kind of thing is this?"

not

"What does this screen mean?"

Text communicates meaning.

Icons communicate recognition.

---

# Design Goals

Icons shall be:

Simple

Clean

Industrial

Technical

Professional

Minimal

Timeless

Readable

Recognizable

Consistent

---

# Visual Style

Project Genesis uses:

Outline-first icons

with

subtle filled variants

for selected or highlighted states.

Icons should resemble:

engineering symbols

industrial control systems

professional software

technical documentation

Avoid decorative illustration.

---

# Inspirations

The icon language is inspired by:

Material Symbols

Lucide

Heroicons

Tabler Icons

Industrial SCADA systems

Engineering diagrams

Modern ERP software

No icon set shall be copied directly.

The final icon family shall be unique.

---

# Grid System

Every icon shall be designed on a common grid.

Recommended:

24 × 24 px

Higher-resolution exports shall preserve proportions.

---

# Stroke Width

All outline icons use a consistent stroke width.

No icon may appear visually heavier or lighter than others.

---

# Corner Radius

Rounded, but subtle.

No sharp industrial corners.

No exaggerated roundness.

---

# Perspective

Flat.

Orthographic.

No perspective distortion.

No isometric projection.

---

# Detail Level

Icons communicate categories.

Not illustrations.

Avoid unnecessary detail.

An icon must remain readable at:

16 px

20 px

24 px

32 px

48 px

---

# Filled Variants

Filled icons may be used for:

selected state

active state

completed state

critical alerts

Default state should remain outline.

---

# Color Usage

Icons inherit semantic colors from the UI.

Icons themselves shall not define colors.

Examples:

Neutral

Information

Success

Warning

Danger

Research

Finance

Transport

Production

---

# Animation

Icons may animate only when representing:

Loading

Progress

Notifications

Warnings

Transport movement

Avoid decorative animation.

# Label Rules

Icons should almost always appear with text.

Exceptions:

Toolbar

Quick Actions

Status Indicators

Compact Lists

Even then:

Tooltips are required.

---

# Accessibility

Icons shall never be the only indicator.

Every icon requires:

Tooltip

Accessible label

Keyboard support where interactive

Semantic meaning
