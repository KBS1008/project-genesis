# VISUAL STYLE GUIDE

**Project:** Project Genesis

**Version:** 1.0

**Status:** Planning

---

# Purpose

This document defines the visual language of Project Genesis.

It establishes a consistent design system for:

- User Interface
- Dashboards
- Charts
- Maps
- Icons
- Windows
- Panels
- Tables
- Buttons
- Notifications
- Illustrations

Every visual asset shall follow this guide.

No asset may define its own visual language.

---

# Design Philosophy

Project Genesis is not a fantasy game.

It is not a cartoon.

It is not a mobile game.

It is not a cyberpunk interface.

Project Genesis should feel like:

• an industrial control center

• a corporate management platform

• an engineering workstation

• a modern ERP system

• a business intelligence dashboard

The interface shall communicate:

precision

clarity

efficiency

professionalism

industrial aesthetics

---

# Core Design Principles

Everything serves information.

Decoration never dominates information.

Every visual element must answer one of three questions:

What happened?

What is happening?

What should the player do?

# Color Philosophy

Color communicates meaning.

Color is never decorative.

Every color has semantic meaning.

Primary colors represent interaction.

Secondary colors represent organization.

Accent colors represent important information.

Danger colors represent critical problems.

Success colors represent completed actions.

Neutral colors represent background information.

---

# Theme

Primary Theme

Dark

Secondary Theme

Light (future)

Dark mode is the primary design target.

---

# Background Hierarchy

Application Background

Workspace Background

Panels

Cards

Inputs

Buttons

Selections

Hover States

Dialogs

Every layer must be visually distinguishable.

---

# Typography

Readable.

Professional.

Minimal.

No decorative fonts.

Use one primary font family.

Use consistent font scale.

Hierarchy:

Application Title

Page Title

Section Title

Card Title

Body

Caption

Metadata

Numbers should align consistently.

Large financial values should be easy to scan.

---

# Spacing

Use a consistent spacing scale.

Never use arbitrary spacing.

Margins

Padding

Card spacing

Panel spacing

Toolbar spacing

Dialog spacing

must follow one spacing system.

---

# Borders

Subtle.

Functional.

Used only where separation is required.

Avoid excessive outlines.

---

# Shadows

Soft.

Minimal.

Used to separate layers.

Never dominate the interface.

---

# Rounded Corners

Moderate.

Consistent.

Do not mix different corner radii.

---

# Icons

Icons communicate actions.

Text communicates meaning.

Icons should never replace text entirely.

Every icon family must share:

stroke width

perspective

corner radius

visual weight

---

# Charts

Charts communicate trends.

Never decorate charts unnecessarily.

Animations should support understanding.

Not entertainment.

Charts must remain readable with many data points.

# Company Management

business software

---

# Notifications

Information

Success

Warning

Error

Critical

Every notification must:

be immediately understandable

be dismissible where appropriate

not interrupt gameplay unnecessarily

---

# Empty States

Every empty state should explain:

Why is this empty?

What can the player do?

Never display empty panels without explanation.

---

# Loading States

Skeleton loading preferred.

Avoid blocking screens.

Loading indicators should remain subtle.

---

# Error States

Errors should explain:

What failed?

Why?

What can the player do?

Avoid technical language.

---

# Animations

Animations support orientation.

Never distract.

Recommended:

panel transitions

dialog transitions

chart updates

notifications

selection

Avoid excessive motion.

---

# Accessibility

High contrast.

Keyboard navigation.

Visible focus.

Readable fonts.

Color is never the only indicator.

Every chart must have textual interpretation.

---

# Responsive Behavior

Desktop first.

Large monitors supported.

Minimum supported resolution documented separately.

Panels should resize gracefully.

---

# Data Density

Project Genesis is an information-heavy game.

Large amounts of data are expected.

Density is acceptable if:

hierarchy remains clear

spacing remains consistent

typography remains readable
